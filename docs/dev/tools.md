# MCP score tools

MCP 2026-07-28 requests can call `server/discover`, `tools/list`, `tools/call`, and `ping` immediately. Each modern request carries `io.modelcontextprotocol/protocolVersion` and `io.modelcontextprotocol/clientCapabilities` (with optional `io.modelcontextprotocol/clientInfo` and `io.modelcontextprotocol/logLevel`) in `params._meta`; malformed `_meta` objects or non-object `tools/call` `arguments` return JSON-RPC `-32602`. Modern results include `resultType: "complete"` and `io.modelcontextprotocol/serverInfo` in `_meta`. Discovery advertises all supported versions (`2026-07-28`, `2025-11-25`, `2025-06-18`), and both discovery and tool listings return `ttlMs: 3600000` and `cacheScope: "public"`. Any version other than `2026-07-28` in modern `_meta` (including `2025-11-25` or `2025-06-18`) returns JSON-RPC `-32022` with `requested` and `supported` versions before checking 2026-07-28-specific metadata. Cancelled modern requests stay silent once cancellation is handled before publication. Legacy clients use `initialize` followed by `notifications/initialized` before listing or calling tools; legacy initialization accepts `2025-06-18` and selects `2025-11-25` for all other requested versions.

For all supported versions, tools return the typed payload in `structuredContent` and notation reads put the bar-aligned summary in `content[0].text`. Text above 256 KiB is replaced by a short budget notice while `structuredContent` remains complete. Errors set `isError` and carry `error.code` and `error.message`.

## Documents

| Tool            | Arguments and result                                                                                                                                                                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `score_create`  | Supply a template ID or local template path. Omit both to use `Treble_Clef`. Optional metadata fields are `title`, `subtitle`, `composer` and `lyricist`.                                                                                                                                                |
| `score_open`    | Supply a local `path` or base64 `data`, with optional `format`, `filename_hint` and `strict_ids`. Decoded `data` and compressed or binary files are limited to 8 MiB. A `.mscx`, `.musicxml` or `.xml` file path (any letter case) may be up to 64 MiB. Stdio limits the complete request line to 4 MiB. |
| `score_outline` | Read metadata, parts, staff IDs, measures, signatures and excerpts. Page counts can be null until the score has been laid out.                                                                                                                                                                           |
| `score_close`   | Release the document and its named checkpoints.                                                                                                                                                                                                                                                          |

Create and open return `document`, `revision`, `outline` and `diagnostics`. Revisions are canonical unsigned decimal strings. Pass the returned string as `expected_revision` to guard a subsequent operation. Element IDs are persistent strings scoped to the document. Supply an `excerpt` EID to select an excerpt on supported tools. Omitting it selects the master.

## Phrase entry and readback

`score_write_phrase` takes a document and a list of lanes. Each lane starts at a 1-based measure, staff and voice. Staff and voice default to 1. The offset defaults to `"0"` and uses an exact whole-note fraction measured from the beginning of that bar. Concert pitch is the default; set `pitch_mode` to `written` on a lane to enter transposed notation.

Supply the compact notation in each lane's `content` string.

```json
{
  "document": "doc-session-1",
  "expected_revision": "1",
  "lanes": [{ "measure": 1, "content": "[Eb4~ G4]:h Eb4:q r:q |" }]
}
```

Separate musical events with whitespace. Use a spelled pitch such as `Eb4` or `C###4` with up to three sharps or flats, a drum key such as `d36` (0 through 127), or `r` for a rest. Chords use brackets, as in `[Eb4 G4]` or `[d36 d42]`. Select ties with `~` inside a chord, or append it to a note or chord to tie every member; rests and graces cannot be tied. Main events default to a quarter note. Duration suffixes take positive whole-note fractions whose reduced denominator is a power of two up to 1024 (such as `:3/8`) or the shorthands `:w :h :q :e :s :32 :64`, with up to two augmentation dots; use tuplets for triplets and other non-binary rhythms.

Use `|` to check a measure boundary, including pickups and local staff meters. A tuplet uses `actual:normal(...)`, as in `3:2(A4:e G4:e F4:e)`. Its members may be notes, chords or rests. Before-graces use `acciac`, `appog`, `grace4`, `grace16` and `grace32`. After-graces use `after8`, `after16` and `after32`. Each wraps a note or chord with an optional duration, as in `acciac([D5 F#5]) E5:q after16(D5)`. Fixed kinds default to and require their named duration (`1/4` for `grace4`, `1/8` for `after8`, `1/16` for `grace16` and `after16`, `1/32` for `grace32` and `after32`); `acciac` and `appog` default to `1/8` and accept any standard note value up to `1/4`.

Each lane needs a musical event or tuplet. Content is limited to 65,536 Unicode characters. Use canonical decimal integers without leading zeros or `-0`. Syntax errors identify the lane, zero-based item (and tuplet member), and escaped offending token or end of content. Score edit rejections give zero-based lane and item indices, counting bar checks.

`score_read_music` starts at `measure` (default 1) and reads `count` bars (maximum 128). Without `count` it reads 4 bars, or fewer when the score ends sooner; an explicit `count` past the last bar is refused with `InvalidArgument`. Restrict the window with 1-based `staves` and `voices` arrays. The payload identifies the selected `score` as `master` or `excerpt`, with the selected EID or null in `excerpt`. Set `include_ids` to address elements in later edits. The summary includes those IDs as `#<eid>` tags. It shows opening staff contexts, bar lengths, repeat markers, signature changes, markings, voice offsets, nested tuplets, graces, ties, measure repeats, spanners and voltas. It ends with `... [truncated]` if it would exceed 32,768 bytes. The typed result also provides elapsed durations, concert and written note spellings, and drum kit names. Written meters retain their spelling, including `6/8`.

- Each `staves[]` entry gives the opening `clef` (such as `G`, `F` or `C3`) when the staff has one and omits the key otherwise. The summary's `Staff` line shows it, as in `Staff 1 Piano clef=G time=4/4 key=0`. The opening header clef is not repeated in bar 1's `markings`; later clef changes are.
- `score_outline` signatures carry the `id` of their time signature, key signature or tempo marking whenever it has one; `score_read_music` signature changes carry it only with `include_ids`. A tempo applies to the whole system, so its `staff` is null in both. The summary tags each change with `include_ids`, as in `time(s1)=4/4@0#<eid>`, and shows authored tempo words, as in `tempo="Andante" 120bpm@0`.
- A bar with markings has a `markings` array; a bar without any omits the key. Each marking has an `offset` from the start of the bar and a `scope` of `system`, `instrument`, `staff` or `voice`. Staff-scoped markings add a 1-based `staff`; voice-scoped ones add `staff` and `voice`. Instrument-scoped markings (dynamics and expressions that apply to every staff of their part, the default for those) add the 1-based `staff` they are anchored on and no `voice`; they appear whenever any staff of the part is selected, so the anchor may lie outside `staves`. With `include_ids`, a marking carries its `id` when it has one. A marking on an event has an `attachment`. That object holds the event's EID in `event` with `include_ids`, and `grace` (`side` `before` or `after`, a 1-based `ordinal`, and the grace chord's `id` with `include_ids`) when the marking belongs to a grace chord. Without `include_ids`, an attachment that has no grace is omitted.
- Marking `type`s and fields are `dynamic` (`value`, optional `custom_text`), `fermata` (`symbol`), `harmony` (`text`), `text` (`kind` `expression`, `staff_text`, `system_text` or `rehearsal_mark`, and `text`), `articulation` (SMuFL `symbol`, `ornament: true` for ornaments), `lyric` (1-based `verse`, `text`, `syllabic` unless `single`, and `melisma` length), `arpeggio` (`subtype`), `tremolo` (`subtype`; a two-chord tremolo adds `two_chord: true`, its `end` position, and `end_event` with `include_ids`), `clef` (`clef`, for clef changes after the opening header clef) and `barline` (`subtype`, for barlines other than normal and repeat barlines).
- The summary lists a bar's markings on one `marks:` line under its `Bar` line, separated by `·`. Each item is the scope (`s1` for staff, `s1v2` for voice, `inst(s1)` for an instrument marking anchored on staff 1, or nothing for system markings), the offset, an optional `grace(before:1)` tag, the payload and, with `include_ids`, `#<eid>`. An example is `marks: @0 rehearsal_mark "A" · inst(s1) @0 p · s1v1 @0 grace(before:1) artic(articStaccatoAbove) · s1v1 @1/4 lyric[1] "la"`. A repeat end (`:|` or `:|x3`) closes the bar's last voice line, or its `Bar` line when no voice is selected.
- Spanners and voltas report sparse details: `direction` for slurs, `niente` for hairpins with a circled tip, `text`, `begin_text`, `continue_text` and `end_text` as plain text (formatting tags removed) where authored, and `begin_hook` or `end_hook` for pedal and text lines. Hairpins carry a `subtype` of `crescendo`, `diminuendo`, `crescendo_line` or `diminuendo_line`, as do glissandos (`straight` or `wavy`), trills and ottavas. The summary's `Spanners:` and `Voltas:` lines separate their items with `·`, like `marks:`. Each spanner shows its subtype and details, as in `HairPin(crescendo) 1@0(s1v1)-2@0(s1v1) niente`, and the line marks with `←` a spanner whose start bar resolves to a bar before the window's first bar. An endpoint whose bar the selected score does not list reports a null `measure`, shown as `?` in the summary (such a spanner gets no `←`). An endpoint without a staff or voice, as on some system-wide lines, reports null `staff` or `voice`; the summary then drops that part of the `(s1v1)` suffix, or the whole suffix.
- The summary quotes and escapes all authored text (tempo words, lyrics, harmony, text markings and spanner text) and escapes part names. It escapes backslash, double quote, ASCII control characters and the Unicode line separators U+0085, U+2028 and U+2029, so authored text cannot start a summary line. Invalid UTF-8 becomes U+FFFD before the 32,768-byte cap applies, so serialization cannot push the summary past it. `structuredContent` keeps the text unescaped.

## Edit, query and checkpoints

`score_edit` applies up to 1024 operations in order. Atomic mode is the default. With `atomic: false`, an execution rejection can leave an applied prefix. The error reports the failing operation index, applied count and revision when available. Set `detail: true` for per-operation created-element slots. Use a bare EID for a persisted target. Within a batch, `{"from_op":0,"item":1}` refers to item 1 of operation 0. Both indices are zero-based.

Use `runtime_info` with `{"scope":"ops","op":"enter_notes"}` for the fields and example for one operation. Bar, staff and voice numbers in edits are 1-based, and offsets are exact whole-note fractions from the start of the bar. The engine resolves each number when its operation runs, against the score as the earlier operations of the batch left it. After `insert_measures` before bar 2, bar 2 is the inserted bar. After `add_part` before the first part, staff 1 is a staff of the new part. After a `set_time_sig`, offsets follow the new bar length. A bar or staff number past the end of the score, an offset at or beyond the bar's length, or a compact position with no event at its onset rejects that operation with `EditRejected`. The message names the operand and the 1-based number, as in `end: the score has no measure 5 (4 available)`. Entering notes at an offset inside a sounding chord is refused with `InvalidArgument`, because that chord cannot be split there. Atomic batches roll back; `atomic: false` keeps the applied prefix. Cooperative cancellation is polled before decoding, every ≤4 KiB during zero-ZIP rollback snapshot capture (`Document::Impl::capture_rollback_snapshot()` for structural atomic batches), and after batch preparation immediately before execution starts (prefix mode, empty batches, and snapshot-free `EditDeltaLog` atomic leaf batches); if observed before execution starts, no operation applies and the revision stays unchanged (a late notification arriving once execution starts may allow the commit to finish, and `notifications/cancelled` suppresses the response on the wire).

- `at` on `enter_notes`, `enter_drums`, `insert_clef` and `add_text` takes a compact position `{"measure":1,"staff":1,"voice":1,"offset":"3/8"}` (measure-local `offset`). Staff and voice default to 1 and the offset to `"0"`. It also accepts an explicit `{"kind":"segment",...}` address with a measure EID and a score-wide `tick`.
- `add.anchor`, `add_spanner.start`, `add_spanner.end` and `add_spanner_to_bar_end.start` take the same compact position, an EID, a segment address or `{from_op,item}`. A compact anchor names the onset in that staff and voice; an articulation needs a chord there.
- `insert_measures.before`, `remove_measures.first` and `.last`, the `measure` of `set_time_sig`, `set_key_sig`, `set_layout_break` and `set_repeat_barlines`, `add_volta.first_measure` and `.last_measure`, and `add_spanner_to_bar_end.end` take a bar number, a measure EID or `{from_op,item}`.
- `set_key_sig.staff` and `remove_staff.staff` take a staff number, a staff EID or `{from_op,item}`.
- `set_repeat_barlines.count` is the number of passes, from 2 through 1024.
- Part operands (`add_part.before`, `remove_part.part`, `add_staff.part` and `generate_excerpts.parts`) take a part EID or `{from_op,item}`.
- Other operands (`set_pitch.note`, `set_duration`, `remove`, `add_tie`, `add_tuplet`, `add_grace_chord` and the property operations) take only an EID, a segment address or `{from_op,item}`.

No edit operand accepts a `page`, `system` or `spanner_segment` address, because layout builds those elements. The published `score_edit.ops` item schema is one flattened object, so a field name shared by several operations (`before`, `start`, `end`, `first`, `last`, `kind`) lists every shape any of them accepts. Before the batch runs, the server checks each operation's exact fields and shapes and refuses one that belongs to another operation with `InvalidArgument`.

Set top-level `excerpt` to an excerpt EID to scope the whole batch to that excerpt. Bar and staff numbers then count the excerpt's own bars and staves, so excerpt staff 1 can be a different master staff. Every EID and segment address in the batch must belong to that excerpt. Operations that change the whole document (`insert_measures`, `remove_measures`, `set_time_sig`, `set_repeat_barlines`, `add_part`, `remove_part` and `generate_excerpts`) are refused with `InvalidArgument` before the batch runs, so no operation of the batch applies, even with `atomic: false`. `set_style` without its own `excerpt` styles the batch's excerpt, or the master when the batch has none. A `set_style.excerpt` that differs from the batch's `excerpt` is refused.

Tonal pitch classes (`tpc`) range from -8 through 40. The runtime catalogue supplies property and style value kinds. Values use JSON booleans, numbers, strings, integer lists, `null`, and named objects such as `{"x":1,"y":2}` or `{"r":0,"g":0,"b":255,"a":255}`.

`score_query` accepts four modes. `elements` takes optional `query` filters and pagination. Select an excerpt with top-level `excerpt` or `query.excerpt`. If both are present, their EIDs must match. `properties` takes a `target` (an EID or any address, including `page`, `system` and `spanner_segment`) and optional list of `props`. `page_count` prepares layout. `audio_tracks` returns the selected score's playback tracks and default mix. Both `page_count` and `audio_tracks` accept top-level `excerpt`. An `elements` result reports a 1-based `measure_number`, `staff` and `voice` for each element, each null when the element has none, as for a part.

`checkpoint`, `restore_checkpoint` and `drop_checkpoint` each take a document and name. Checkpoints share a 64 MiB in-memory budget; a checkpoint that does not fit returns `ResourceLimit`. `checkpoint` polls cooperative cancellation while queued and every ≤4 KiB during snapshot capture; if observed before the snapshot is stored, nothing is saved or overwritten under the name (a late notification after capture finishes may still store the checkpoint, with the wire reply suppressed by `notifications/cancelled`). Restoring a checkpoint advances the revision and preserves public IDs. A document that reports a poisoned edit can be recovered by restoring a checkpoint or reopening the file.

## Export and runtime

`score_export` takes a document, format and local path. PNG and SVG use a directory containing one file per page. Other formats take a file path. PNG defaults to an opaque white background. Set `options.background` to false and `options.transparent` to true for transparency. Use `first_page`, `last_page` and PNG `dpi` in `options` to control rendering.

Available formats are `mscz`, `mscx`, `musicxml`, `mxl`, `midi`, `pdf`, `png`, `svg`, `wav`, `flac`, `opus`, `mp3`, `measure_positions` and `segment_positions`. Position exports contain page-local 1200-DPI geometry and repeat-expanded playback times in milliseconds. Success reports the source revision, published artifacts with integer byte sizes and any engine warnings. Publication failures identify files already visible. An audio export renders in the background after reading the document, so the document may be queried, edited or closed meanwhile; its `source_revision` is the revision it read. Audio exports run one at a time: a later one waits for the current one, and cancelling it while it waits drops it at once.

Native exports use version 5.00 by default. Set `options.native_version` to `"4.70"` for compatibility export. Inspect degradation warnings and refusals before distributing the result. [Engine compatibility details](../../vendor/engrave/docs/write470.md)

`runtime_info` returns capabilities, limits and tool revision. `limits.input_bytes` and `limits.uncompressed_file_bytes` give the two `score_open` input bounds. Select `overview` (default), `templates`, `instruments`, `types`, `type`, `styles` or `ops` with `scope`. Only `instruments` accepts `query` and matches substrings of the instrument ID, name or group ID with ASCII case folding. For a single type use its `type` name, or use `op` to look up a single operation. `runtime_configure` accepts an `add_font` path and an ordered `soundfonts` list. A combined request applies both changes atomically. An empty list clears the SoundFont selection. An audio track can select a SoundFont by zero-based index, configured source path, private copy path, filename or stem.
